## 直接回答用户的问题

1. **"max_batch=4" 是我之前的粗略估计,实测证伪为"看 L 而定"**:对中小复合物(L≲600)B=6、甚至 B=8 都不 OOM;对大复合物(L~800)B=6 就 OOM(max 4);L~1000 B=3 就 OOM(max 2)。4 只是 L~550–830 的中位值。
2. **"B=6/8/10 会 OOM 吗":分复合物**——小/中(L≲600)不会;大(L~800)B=6 OOM;很大(L~1000)B=3 OOM;巨大(L>1500)B=1 都 OOM。
3. **ESM3dG:StaB 有效 batch 比值(StaB=`10000//L`,均受 #mut 封顶):非单值,随 L 变**:
   - 巨大复合物(L>1500):**StaB 能训(batch 2–5)、ESM3dG 完全训不了(skip)→ 比值 ∞**;含 **1KBH(85 突变,最富数据的复合物)**、3VR6、4GXU。
   - 大(L~800–1030):**~3–4.5×**。
   - 中(L~300–600):**~2.5–7.5×**。
   - 小(L<200):token-budget ~13–21×,但两边都 #mut-capped、不咬。
   - **对指标真正重要的多突变复合物(L~400–1030):StaB 有效 batch ≈ ESM3dG 的 ~3–5×**(不是我早先估的 8–10×——因为 L 越大 StaB 的 token-budget batch 也越小、部分抵消)。

## 更重要的两个发现(超出原问题)

**A. finetune.py = 每个 chunk 一次 optimizer step,无梯度累积**(`esm3dg_stab/finetune.py:134-144`:`for s in range(0,n,Mtry): zero_grad→forward→backward→step`)。
→ ESM3dG 每复合物每 epoch 做 `⌈#mut / maxbatch(L)⌉` 次更新;StaB 的 token budget 通常 ≥ #mut → **1 次/复合物**。**同 epoch 下 ESM3dG 的 optimizer step 多 ~3–5×、更 noisy → 过拟合更快**。用户的过拟合担忧被代码 + 实测双重坐实。
→ **修法**:(a) **梯度累积**——把一个复合物的所有 chunk 累积成 1 次 step,更新粒度 + 有效 batch 对齐 StaB,step 数降 ~3–5×;(b) val-based early-stop / best-val 选模型(真正的过拟合闸)。

**B. 3 个最大 train 复合物连 B=1 都 OOM → 现在被 `oom_skipped_complexes` 完全丢弃**:3VR6(L=3399,16 mut)、**1KBH(L=2122,85 mut)**、4GXU(L=1930,3 mut)= ~100 个突变的训练信号被丢,含**单个最富突变的复合物 1KBH**。这可能是之前 fine-tune 偏弱的原因之一。
→ **修法**:对 ESM3 trunk 开 **gradient/activation checkpointing**(拿计算换显存,O(L²) 激活的标准解法),把这些大复合物拉回可训练区;或接受 skip(损失信号)。
